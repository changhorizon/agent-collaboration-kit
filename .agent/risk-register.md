## R-001 — 跨项目交接将单个源码仓库路径误填为协调 cwd

- 状态：Open（Kit 机制待优化；本项不表示既有协议允许绕过 cwd 一致性检查）。
- 严重度 / 可能性 / 影响：低至中 / 跨项目任务可能复现 / Lead 与 Advisor 实际在共同父目录启动，却把某一源码仓库路径写入消息 `cwd`，导致收件方按协议暂停交接。
- [E] 原始证据、对象与版本：某跨项目任务（项目名与本地绝对路径已脱敏，不写入公开仓库）的 lead→advisor 请求将 `cwd` 误写为该任务某一源码仓库的子路径 `source/`，而非两会话实际共同启动的父目录；Kit `main@66af5f4` 的 `.agent/exchange/README.md` 公共头部定义 `cwd` 为发送方工作目录，且要求收件方核对目录一致性。会话启动目录的工具级实测原件未在此登记。
- 当前缓解措施、剩余影响：由 Lead 保留 M001、追加更正请求并 `supersedes: M001`，以实际共同工作目录填写 `cwd`，给出各仓库的独立路径/版本和固定的共享信箱绝对路径，再转发指向新消息的通知；收件方仍须核对实际 cwd，不因父目录可访问子目录而忽略不一致。更正是否已经落盘、Advisor 是否接手，需从任务信箱与会话分别核实。
- 待优化建议（未裁定为协议变更）：跨项目任务开始时，由用户选定或确认协调工作目录，通常可选各参与项目的最近公共目录，但应以 Lead 实际启动/工作目录及独立收件角色实际可对齐的目录为准；消息 `cwd` 记协调会话的真实目录，而非随意选一个仓库的 `source/`。共享信箱位置、参与仓库路径/版本、项目各自规则另行登记，不把“可访问”误作“cwd 相同”。Lead 实际 cwd 与用户期望不符时先对齐会话或说明差异，不只改信头冒充已切换。
- 负责人 / 停止点 / 重开条件：Kit 后续维护者核对跨项目接入流程后决定是否更新交接指引及沙盒案例；改协议前保留现有不一致即暂停的安全边界。再次出现父目录协调任务、项目本地协议优先级差异或跨 worktree 交接时重开验证。
- 触发的 Reviewer / Auditor / Advisor / 用户授权规则：本条仅登记运行中的使用摩擦与改进建议；是否构成交付协议变更及相应审阅触发，待实际改动时判定。
- 用户接受时的对话依据、范围与时间；未接受则写未接受：用户提出记录与优化方向，不等于接受绕过目录检查的风险或授权变更 Kit 协议。
- 最后复核时间：2026-10-09（本次对话登记；未核实精确 UTC 时刻）。
